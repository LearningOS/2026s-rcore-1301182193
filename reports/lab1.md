#实验报告

##1.实现的功能
    本次实验实现了 sys_trace系统调用 sys_trace(trace_request, id, data)。当 trace_request = 0时，
读出以 id 为地址的值并返回 ；当 trace_request = 1时，将 data 写入 id 所指向的数据，并返回 0；当 trace_request = 2时，返回该次任务中，以 id 为编号的 syscall 的被调用次数

##2.问答题
    ###1.
        (1)ch2b_bad_address: 提示页错误，bad addr = 0x0, bad instruction = 0x804e03a4。访问了错误的地址空间
        (2)ch2b_bad_instructions: 在用户态使用了特权指令 “sret“，权限不足，应用被内核 killed
        (3)ch2b_bad_register: 尝试在用户态使用汇编指令 “csrr“ 读取 内核态csr 寄存器 sstatus，内核认为这是非法的指令，将应用 kill
    
    ###2.
        (1)刚进入 _restore时，sp 代表内核栈的栈顶指针，
            _restore的两种使用场景：运行第一个应用程序时；处理完中断后，从内核态切换回用户态时；
        (2)通用寄存器:t0, t1, t2, csr 寄存器:sstatus, sepc, sscratch
            通用寄存器的作用：作为中转，将内存中的值转移到 csr 寄存器中，因为在 riscv 指令集下，不可以直接实现内存和 csr 寄存器的通信
            csr 寄存器的作用：sstatus：记录当前允许的中断状态，1 表示关中断，0 表示关中断
                            sepc：记录切换回用户态后，下一条运行的指令的地址。
                            sscratch：记录内核栈栈顶的位置，为下次中断进入内核态做准备。
    ##3.因为在_alltrap函数里面，没有保存 x2 和 x4寄存器，x4 寄存器是因为应用不会用到这个寄存器
    ##4.在L60:csrrw sp, sscratch, sp 之后，sp 存的是用户栈的栈顶指针，sscratch 存的是内核栈的栈顶指针
    ##5.sret 指令会发生状态切换，这是 riscv 指令集提供的跳转方式
    ##6.在L13:csrrw sp, sscratch, sp 之后，sp 存的是内核栈的栈顶指针，sscratch 存的是用户栈的栈顶指针
    ##7.从 U 态进入 S 态是从 csrrw sp, sscratch, sp 开始的
