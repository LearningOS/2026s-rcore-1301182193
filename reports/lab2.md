# 二、问答作业
## 1.SV39页表 页表项的组成
### 答：
#### [0..9]位,共 10 位为标志位(Flags)；[10..63]位，共 54 位为物理页号(PPN)

[0..7]位，共 8 位为常用标志位，[8..9]位，共 2 位，为待扩展标志位，无具体含义。

第 0 位：V(Vilid):有效位,此位为 1 则该页表项指向的物理页有效，为 0 则该页无效。  
第 1 位：R(Readable)：可读位,次位为 1 则该页表项指向的物理页可读，为 0 则该页不可读。  
第 2 位：W(Writable)：可写位,此位为 1 则该页表项指向的物理页可写，为 0 则该页不可写。  
第 3 位：X(Executable)：可执行位，此位为 1 则该页表项指向的物理页允许取值执行，为 0 则该物理页不可取指执行。  
第 4 位：U(User)：用户态可访问位，此位为 1 则该页表项指向的物理页允许用户态访问，为 0 则用户态不可访问。  
第 5 位：G(Global)：全局映射位，此位为 1 则该页表项指向的物理页对于所有的地址空间可见，为 0 则仅对当前地址空间有效。  
第 6 位：A(Accessed):访问位，此位为 1 则该页表项指向的物理页最近被访问过，为 0 则没有被访问过。  
第 7 位：D(Dirty):脏位，此位为 1 则该页表项指向的物理页最近被修改过，为 0 则没有被修改过。  

## 2.缺页
### 答：
#### 以下三种异常可能是由缺页导致的：  
Instruction Page Fault.   
Load Page Fault.   
Store/AMO Page Fault.  

#### 发生缺页时寄存器的值
scause: [Instruction Page Fault, Load Page Fault, Store/AMO Page Fault.] 中的一个  
stval: 出错的虚拟地址
sepc: 发生 trap 的那条指令的地址
sstatus: 保存陷入前的状态，是用户态还是内核态  

#### Lazy策略有什么好处
1.节省物理空间  
2.减少无意义的页表分配操作  
3.启动更快  
4.支持更大的虚拟地址空间

#### 处理 10G 连续的内存页面，对应的 SV39 页表大致占用多少内存
处理 10G 连续的内存页面，对应的 SV39 页表大致占用 2.5MB内存

#### 应该如何实现 Lazy 策略，缺页时应该如何处理
Lazy: 使用 lazy_static!进行页面的分配。程序加载请求内存时，只分配虚拟页面给它，不分配实际的物理页，等到真正有数据进来时再分配对应的物理页给程序。  
缺页时: 先检查地址 是否属于一个合法映射但未分配物理页面的 地址。     
    如果合法：分配物理页面给这个程序，按照权限填写这个页表项。如果是匿名页，那么清零，如果指向代码段或者文件，从 ELF 或者 FS 中拷入对应数据。然后刷新 TLB，返回用户态，重新执行该指令。  
    如果地址不合法：调用内核杀死该进程。  

#### Swap策略下页面失效如何表现在页表项
页表项的第 0 位，即有效位V(Valid)被置为 0，说明这个页表项是无效的。可以借助保留位，说明该页被 Swap 到了磁盘。

## 3.单页表

### 单页表情况下，如何更换页表
#### 答：  
修改 satp 中的值，指向需要切换到的地址空间

### 单页表情况下，如何控制用户态无法访问内核界面
#### 答：  
将页表项中的 U 标志位设置为 0，在访问时检查是用户态还是内核态，如果是用户态，拒绝访问  

### 单页表有何优势
#### 答：
1.维护方便，分配和回收页表时，可以使用相同的接口  
2.减少用户态和内核态上下文切换里的页表切换的性能开销  

### 双页表何时更换页表；单页表什么时候更换页表
1.双页表在用户态应用切换，用户态陷入内核态，和内核态返回用户态三种情况下切换页表
2.单页表在用户态陷入内核态，和内核态返回用户态时切换页表
